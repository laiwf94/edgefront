# Changelog

Changes to edgefront, newest first. Each week's entries name the roadmap issue they close or advance.

## Unreleased

### Cache

- `edgefront-difftest cache` replays a request log against cachet 0.1 (commit `ed77c32`, the last before the workspace split) and the edgefront binary. It diffs each response's status, headers except `Date`, body SHA-256 and the origin requests behind it. Both nodes run on one logical clock through libfaketime, against identical deterministic origins, so any divergence is a behaviour change. `make difftest-cache` builds cachet 0.1 and replays 50,000 generated requests from a clock seed, in CI on every push; seven local runs found 0 divergences, about 16 seconds each. `--log FILE` replays a recorded log, and `cache-record` writes a generated one. `crates/edgefront/tests/difftest_cache.rs` checks the harness: the binary against itself finds nothing, and a node with one setting changed is caught. (#81)
- cachet's node serves its proxy and admin listeners on `edgefront_core::listener`, the listener the proxy track uses, and cachet's own accept loop (`edgefront_core::server`) is deleted, along with hyper-util's `server` and `server-graceful` features. What a client sees is unchanged: a request head still gets `client_header_ms`, a silent keep-alive connection is still closed after that long unless the new `timeouts.idle_ms` sets another idle timeout, heads over `max_header_bytes` or 100 fields get 431, and shutdown stops accepting, closes idle connections and lets open requests finish with `Connection: close`. Two things differ: the header timer of a later request on a keep-alive connection starts at its first byte rather than when the previous response ends, and connections still open when `shutdown_ms` runs out are now closed instead of left running. (#81)
- cachet is split into the edgefront workspace with no change a client can see (#78):
  - `edgefront-core` holds the accept loop, config loading (`config::loader`), the metrics writers, the admin router with bearer tokens, request ids and the response body type.
  - `edgefront-cache` holds the caching policy, Cache-Control and range parsing, objects, request collapsing, purge, cluster gossip (through a `PurgeHost` trait, so the crate never depends on cachet), the memory and disk stores, and the cache's config sections.
  - `crates/edgefront` is the binary. It takes cachet's flags, `CACHET_*` variables, exit codes and config file unchanged, and logs the same JSON lines under the same targets.
  - The root package keeps the node runtime still to move and the reference `cachet` binary.
- `crates/edgefront/tests/golden.rs` and `tests/golden_cli.rs` hold both binaries to the same command-line transcripts, log lines included. (#78)
- `crates/edgefront/tests/e2e_workspace.rs` runs the demo's five steps against two edgefront nodes and compares every status, `Cache-Status` and body with a fixture byte for byte; `tests/e2e_workspace.rs` runs the cachet binary against the same fixture. `examples/demo.sh` runs the edgefront binary by default and the reference one with `DEMO_BIN=cachet`, and CI runs both. (#78)
- The fuzz targets live in `crates/edgefront-cache/fuzz` and `crates/edgefront-core/fuzz`, and CI fuzzes each of the nine for 10 minutes. The three new core targets (`request_id`, `base_url`, `bearer_token`) found that `http://:80` and `http://origin:8o8o` were accepted as origin URLs; both are now rejected. (#78, #240)
- `make cov` holds every crate to 90% line coverage on its own sources, `make tsan` runs ThreadSanitizer one crate at a time (one CI job each), and `make audit` runs cargo deny on every manifest, cargo audit on every lockfile and a budget of 14 exactly pinned direct dependencies. (#78)

### Proxy

- `edgefront proxy` balances with steer's balancers. Each cluster's `policy` (`round_robin`, `least_loaded` or `maglev` on `hash_header`), endpoint `priority` levels with spill and `panic_threshold_percent` now decide every pick, instead of taking turns over the most preferred endpoints. An endpoint counts a request in flight until its response body is done and observes the time to the response head, at least one second for a failure or a 5xx. When nothing is available and panic is off the answer is steer's `503 no_healthy_upstream`. `Proxy::with_sources` takes the clock and the random source, and `Proxy::endpoints` and `Proxy::balancer` expose each cluster's live state. (#80)
- `crates/edgefront/tests/e2e_port_balancer.rs` sends 20,000 requests per policy to nine origins over three priority levels, with a manual clock and a seeded script of health flips, ejections, latency samples and requests held in flight. All 60,000 picks match steer's balancer, through spill to levels 1 and 2, panic and ejections. The per-endpoint counts and a digest of the picks are checked against a fixture recorded from steer on every run, and `make e2e-steer` runs steer live on the same script. `crates/edgefront-proxy/tests/balancer_properties.rs` checks the whole balancer over random endpoint states: outside panic no pick lands on an unhealthy or ejected endpoint, each level's share of 100,000 picks is within one point of Envoy's priority load, and round robin in panic spreads by weight. The balancers are documented in docs/DESIGN.md and the README. (#80)
- `edgefront_proxy::balancer::Balancer`, ported from steer's `balancer.LB`: the priority decision, a round robin, peak-EWMA or Maglev policy, and the endpoints' live state put together. A pick reads availability at the clock's time, chooses a level by load, or by the key for Maglev, falls back across levels on retries and picks from every endpoint in panic, with every random draw in steer's order. `edgefront-difftest balancer` and a new `picks` query in `legacy/steer/cmd/diffdrive` diff it against steer, pick for pick. Each run covers 1,000 seeded scenarios of 10,000 requests, mixed with health flips, ejections, clock moves, in-flight changes and latency samples. It reports the first differing line with its seed, step and a replay command. `make difftest-balancer` runs it in the legacy-steer workflow on every push. (#80)
- `edgefront_proxy::balancer::maglev`, ported from steer's `balancer.Maglev`: Maglev consistent hashing with weighted turns, a cache of the last 8 lookup tables (one per candidate set), retries that walk forward to the next untried owner and `hash_key` for request keys. Its tables are identical to steer's, checked byte for byte against 143 tables over 50 endpoint sets that `legacy/steer/cmd/diffdrive`'s `TestMaglevVectors` writes from steer, including the 100-endpoint, 65,537-slot table, along with 3,000 keyed and keyless picks. A keyed pick takes about 40 ns over 100 endpoints, and a full table build takes 2.1 ms against steer's 4.0 ms. Candidates that all have weight zero give an empty table instead of steer's division by zero. (#80)
- `edgefront_core::clock`, ported from steer's `internal/clock`: a `Clock` trait over monotonic time and one-shot timers, `MonotonicClock` on tokio's timer, and `ManualClock`, which moves only when advanced and then fires due timers earliest deadline first, ties in the order they were made. Balancing, health checks and outlier detection take it so tests and the difftest can drive time. (#80)
- `edgefront proxy --config <file>` runs the HTTP/1.1 proxy ported from steer, from steer's configuration file unchanged (JSON, or the same schema in TOML). `--check-config` validates a file. The request path matches steer:
  - Go's server checks and steer's JSON errors.
  - Routing on the cleaned path.
  - Forwarding headers trusted only from `trusted_proxies`.
  - Request IDs.
  - Hop-by-hop removal.
  - Each cluster's `max_requests` and `timeout`.
  - One access log line per request. (#77)
- `crates/edgefront/tests/e2e_port_http1.rs` holds the binary to a transcript of 30 requests recorded from steer, covering responses and what the upstream received. `make e2e-steer`, run in CI, also replays the cases against a live steer. (#77)
- `edgefront-difftest` diffs 10,000 generated configs and 100,000 generated requests between `legacy/steer/cmd/diffdrive` and the Rust crates on every push (`make difftest`). (#77)
- Ported from steer: the config loader (`edgefront_core::config`), host and prefix routing (`edgefront_proxy::route`), path cleaning and request targets (`edgefront_proxy::path`), forwarding headers (`edgefront_proxy::forwarded`), request IDs (`edgefront_proxy::reqid`), and the HTTP/1.1 listener and pooled client (`edgefront_core::listener`, `edgefront_core::http1`). (#77)
- Config errors quote values the way Go's `%q` does. (#237)

### Limiter

- The keyed `Table` has no 4.5-year horizon any more either. Each shard keeps a base epoch, one behind the newest timestamp it has seen, and its entries keep arrival times as offsets from it; a timestamp two epochs past the base moves it under the shard lock, in one pass over the shard. Every `u64` timestamp is valid and decisions equal exact arithmetic on absolute time. `EntryState::tat` is now `u128` ticks since the clock's start. The table's reference model checks it at 4.5, 10 and 100 years of uptime, across epoch boundaries with keys in debt and after idle gaps, and the difftest applies pacer's clamp before calling `Table`. Table speed is unchanged. (#82)
- `Gcra` has no 4.5-year horizon any more. It stores its arrival time as an offset from a moving epoch of 2^56 ns and rebases it lock-free when the time it has to store moves on, so every `u64` timestamp is valid and decisions equal exact arithmetic on absolute time. `Gcra::tat` now returns `u128`, and `Gcra::base_epoch` is new. New module `edgefront_limiter::clock`: the epoch arithmetic, a `Clock` trait, `MonotonicClock` and `ManualClock`. The reference model checks the limiter at 4.5, 10 and 100 years of uptime, across epoch boundaries and idle gaps. Below libpacer's horizon nothing changes, and the difftest applies pacer's clamp before calling `Gcra`. (#82)
- `edgefront_limiter::config`: pacerd's config in Rust. `parse_pacerd` accepts and rejects pacerd.conf files as pacerd does, with the same message and line number. `LimiterConfig` also loads through serde as a TOML section that uses pacerd's directive names and value syntax, and writes back out in either syntax. serde becomes the crate's one dependency. (#82)
- New crate `edgefront-limiter`, libpacer's algorithms in safe Rust with no dependencies (#79):
  - `Gcra`: an exact, lock-free token bucket whose arrival time is one `AtomicU64`, with `take`, `take_upto`, `take_range`, `refund`, `remaining` and `reconfigure`, and retry-after times exact to the nanosecond.
  - `Table`: per-key buckets in fixed memory, sharded, with idle reclaim, deny or evict when full, holds, sweeps and stats. Keys are hashed with SipHash-1-3 by default, or SipHash-2-4 to place keys as libpacer does.
  - `Window`: a sliding-window counter for quotas.
- The keyed table takes about 60% more decisions per second than libpacer's with spread keys and 25% more with one hot key on the same machine, where it took 15 to 30% fewer before: the SipHash tail is built in registers instead of reloaded from a byte buffer, which stalled every hash on store forwarding, and table entries are aligned to cache lines. Numbers are in docs/DESIGN.md. (#79)
- Rates whose burst times interval overflows are refused with `InvalidRate`. libpacer wrapped them to a zero tolerance and then divided by zero. (#79)
- `legacy/pacer` holds pacer with its full history. Its own gate (sanitizers, coverage, fuzzing, demo and image) runs in CI while it exists. (#79)
- `legacy/pacer/tests/diffdrive.c` and `edgefront-difftest pacer` diff generated operation scripts between libpacer and edgefront-limiter, comparing every decision, retry time and state. The first difference is reported with its seed, step and a replay command; `make difftest-pacer` runs 100 scripts of 10,000 operations from a clock seed. (#79)
- `crates/edgefront-difftest/tests/e2e_limiter_port.rs` runs one million differential operations on every push, checks that a divergence replays from the command it prints, and walks through per-key limits, retry times and an hourly quota with the answers written out. (#79)
- `crates/edgefront-limiter/tests/model_gcra.rs` checks `Gcra` against a token bucket in exact rational arithmetic, from seeds and from a shrinking proptest tape. (#79)
